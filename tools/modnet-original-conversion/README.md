# Independent authors-checkpoint MODNet conversion

This is a hosted-only provenance remedy for #55, not a new model offering or runtime replacement. The current tested ONNX stays unchanged. No local conversion, inference, download, dependency installation or artifact dispatch was performed to prepare this source.

The authors' pinned [pretrained README](https://github.com/ZHKKKe/MODNet/blob/28165a451e4610c9d77cfdf925a94610bb2810fb/pretrained/README.md) links Drive folder `1umYmlCulvIFNaqPjwod1SayFmSRHziyR`. The connected folder listing on 2026-10-19 identified photographic checkpoint `1mcr7ALciuAsHCpLnrtG_eop5-EYhbCmz`, 26,255,603 bytes, modified 2020-12-07T05:21:01.930Z. Listing is identity evidence, not binary verification/public availability. Its separate ONNX entry is not an original checkpoint and is not substituted. Authors' [license declaration](https://github.com/ZHKKKe/MODNet/blob/28165a451e4610c9d77cfdf925a94610bb2810fb/README.md#license) covers code/models under Apache-2.0, excluding example GIFs.

The manual workflow has two deliberately separate executions:

1. **capture**: official pinned Python Linux AMD64; resolve only wheels for the pinned CPU Torch/ONNX/ORT candidates and image preprocessing. Download each resolved wheel with an exact hash, inspect metadata/notices, emit a complete requirements hash lock and source URLs, then remove wheels. This does not import those packages. It may acquire only the exact author-linked checkpoint, enforce its observed byte count, record its SHA and requested/final URLs, and delete it without deserializing. Google access/challenge HTML is a failed acquisition, not a reason to use a mirror or bypass. No checkpoint binary enters delivery. The core metadata comes from official CPU/PyPI indexes; these are candidates, not a complete reviewed lock or blanket security certification. Historical Torch 2.6 is not used; the previous advisory audit found later affected versions. Full transitive lock/security/size review happens on this actual output.
2. Commit the reviewed `wheel-lock.json`, `requirements.lock` and exact checkpoint SHA under `tools/modnet-original-conversion/reviewed/`, changing `reviewedForConversion` to true. **convert** refuses an absent/unreviewed lock. It reacquires the same checkpoint and requires that reviewed SHA. Install only locked wheels offline, then run CPU conversion offline with the pinned author source read-only. Safe loading uses `weights_only=True`, bounded plain finite tensors, exact state keys/shapes/dtypes, explicit CPU/float32, and strict loading of both original and export-specific architectures. No custom pickle allowlist, CUDA, pretrained-backbone download, quantizer, post-export optimizer or unreviewed fallback.

Conversion exports explicit opset 11, dynamic batch/height/width, legacy `dynamo=False`, no external data. It records built-in Torch exporter transformations honestly. Numerical comparison uses original PyTorch final matte, author export-specific graph and NEW ONNX on identical tensors: retained licensed fictional portrait plus five deterministic resize derivatives. Maximum/mean tolerances are 1e-4/1e-5 and final alpha8 max1/mean0.1. Failures remain failures, not relaxed thresholds. This proves conversion equivalence for these finite fixtures, not visual quality on every portrait or the historical community conversion. Existing normal Neo cutout quality/original-byte/save acceptance must be repeated before explicit new registry adoption.

All final outputs, source/license/notices, lock and receipts are recipient-encrypted in the runner. No public plaintext model/source archive, private key, paid provider, model registry change or runtime activation. The capture output contains metadata only, but follows the same encrypted delivery. Resource failures stop without cap increases or retry. Existing browser/backend digest and size contracts must change explicitly in a later reviewed adoption; this workflow does not change them.
