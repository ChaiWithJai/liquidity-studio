# Native connection proof (C1 only)

This original first-party page proves the current native profile. It grants no editing, team membership, sharing, asset or collaboration authority. The later paired-access and live-fence slices remain required before governed editing activation.

Mount `createNativeConnectHandler` from `server/penpot-native-connect-proof.js` in an original private adapter. Its constructor receives a private 32-byte hex gateway key, fixed native instance UUID, fixed Studio origin and a proof sink. `createNativePairingProofSink` sends only the opaque challenge, native instance UUID, actual profile UUID and optional actual fullname to the fixed `/api/native/penpot/pairing/proof` endpoint using a **separate** private pairing key. Native cookie values are neither persisted nor forwarded to Studio. No browser-supplied profile, instance, callback or Studio actor is accepted.

The `server.conf.example` has two exact native-frontend routes. A private read-only include overwrites the gateway header with the generated key. Do not put its value in Git, command arguments, browser HTML or logs. The adapter and gateway must disable request/header/body logging; native challenge URLs and session headers are private. Keep the existing native frontend/backend and unrelated work unchanged. The example is source preparation, not a deployed configuration or proof of native operation.

Studio issues a short-lived 43-character base64url challenge from a fresh authenticated session. The native GET renders an inert confirmation form. Deliberate same-native-origin POST reads the presented `auth-token` through the fixed official `get-profile` command and records the proof. The native response strips email and all other profile data. Studio completes pairing only after fresh same-session authentication and explicit confirmation, with its existing expiry/replay/current-scope checks. The native page's Return link goes to the configured Studio origin; it does not complete pairing automatically.

Private adapter admission, mounting and runtime acceptance require integration review. No native Clojure build, arbitrary RPC relay, stored operator cookie or frontend identity claim is involved. Hosted tests cover exact profile transport, cookie isolation, inert GET, deliberate confirmation, fixed callback and bounded errors. Local tests/runtime were not run during preparation.
