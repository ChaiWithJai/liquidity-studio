# Owned Penpot image readiness experiment

Source-only candidate for Penpot 2.18.3 at upstream commit `ff7a66f51938b2293260ea27a64e2c4e0833b5e3`. Nothing in this directory establishes repaired PNG pixels or starts a renderer.

The pinned [bitmap exporter](https://github.com/penpot/penpot/blob/ff7a66f51938b2293260ea27a64e2c4e0833b5e3/exporter/src/app/render/bitmap.cljs) waits for navigation, fonts and a visible capture target before taking its screenshot. A successful image HTTP response does not itself establish image decode completion. Our cultural PNG omitted a successfully delivered image; existing second-resolution logs cannot establish causality. This experiment tests that hypothesis while preserving the original screenshot function and ClojureScript arity dispatch.

`prepare.py` requires the exact official image digest, compiled file SHA/size, unique screenshot seam and main entry. It appends the original-owned wrapper before startup and writes the derivative and hash receipt only into a new private directory outside Git. It does not invoke Docker, compile upstream code, install packages or run tests. Keep the original compiled file, source map, license notices and failed outputs unchanged. No upstream compiled artifact is committed here.

The private manifest has only `frameIds` and `imagePaths`: one to eight exact owned UUID frame IDs and one to eight exact native `/assets/by-file-media-id/UUID` or `/assets/by-id/UUID` paths. Never put credentials in it. For SVG images in those frames, the wrapper permits only the existing fixed native origin and listed paths, rejects query/hash/unknown references, decodes at most eight images of at most 1024×1024 pixels each, then waits two animation frames. Decode plus animation-frame readiness has a 15-second deadline. Decoded memory is bounded to eight million pixels (about 32 MiB for RGBA, excluding browser overhead). It retains the decoded images through the original screenshot and clears its own capture hold afterward. Failure rejects before screenshot; it creates no substitute output. Frames without image nodes retain the original capture path.

Logs include counts, dimensions and request/decode/capture timing, without resource URLs, cookies, options, output paths or upstream exception bodies. They are diagnostic evidence, not authorization evidence. Existing presented-native-cookie, current Studio membership/source/binding and asset checks remain unchanged; no shared cookie, public bypass, positive authorization cache or alternate renderer is introduced.

Before preparing a candidate, review the exact source packet and private manifest. Before any mount, record the existing exporter configuration, original file SHA and image digest, consistent owned SQLite/native PostgreSQL backups, and generated receipt. Use `compose.review-only.yaml` only with the existing owned `penpot-native39` project and a reviewed absolute private `PENPOT_QA_IMAGE_READINESS_APP` path. It adds one read-only file mount; it changes no ports, credentials, resource limits or other services. Existing exporter limits remain 1 GiB memory, 1.5 CPU and 256 MiB shared memory. Coordinate the single heavy rendering slot before recreating the owned exporter or producing one candidate PNG.

Acceptance requires an actual Neo-controlled PNG containing the expected portrait and preserved text, matched to source/native/output hashes and the new timing evidence; HTTP 200 or hook logs alone do not pass. Compare against preserved finance and cultural outputs. The standalone SVG pass is separate evidence. Do not rerun staging, modify native content or claim archive recovery from this experiment.

Rollback removes only this overlay and recreates only the owned exporter from its original pinned configuration, preserving volumes and all other applications. If the private asset ingress is also active, restore its frontend base before stopping its callback. No maintained Studio or cloud service changes are authorized by this packet.

Hosted tests exercise the hook with constructor/VM doubles; they are not browser rendering proof. They have not been run locally under the current Neo-only testing constraint.
