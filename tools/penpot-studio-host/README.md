# Studio workspace UI-state bridge

Approved #283 second increment, pinned to Penpot `ff7a66f51938b2293260ea27a64e2c4e0833b5e3`. This small frontend module reports UI state only. It neither grants access nor accepts native commands, credentials, source text or save requests.

The workspace mounts the bridge for its current file and removes its state watch/message listener on exit. Missing/unready file data or persistence state is unknown. Active text edition, transform or drawing is unfinished even if the earlier persistence queue was saved. Saved requires the actual saved status, empty queue and a valid native revision. Existing native persistence, editing and export code is unchanged.

The constructor supplies `PENPOT_STUDIO_ORIGIN` to the reviewed official frontend entrypoint. That writes a public `penpotStudioOrigin` global into existing config.js; unset removes a prior value and disables the module. Only an exact HTTPS origin is accepted. Keep this origin equal to the managed configuration and frame policy. No secret enters browser configuration.

Studio sends `studio-penpot-observe` version 1 with the expected file ID and a fresh 43-character per-document nonce. Native accepts only the configured exact parent origin and actual parent window, and only its mounted file. Native returns `studio-penpot-state` with that nonce/file, page, revision and one of unknown/editing/pending/saving/saved/error. Studio accepts only the exact frame window and native origin, matching nonce/file and finite state/revision. It does not mark a frame load Saved. A one-second observer handshake lets a slowly loaded workspace join; state updates are deduplicated between handshakes. Navigation/reload retains conservative protection unless native reports Saved.

`apply.py <upstream>` hash-checks the finite original files and patch/copy inputs before applying. The existing encrypted `penpot-font-ui-candidate.yml` workflow applies the module after the independent fonts/thumbnail patches, compiles the complete frontend and runs the existing thumbnail test namespace plus the new pure state-classification namespace. No local compiler or tests ran. Corresponding source, tests, patches, manifest and the modified entrypoint are included only in encrypted delivery.

Runtime adoption needs both the complete verified frontend bytes and `nginx-entrypoint.modified.sh` at the existing official entrypoint path, retaining its executable mode, plus the exact optional origin environment value. The frontend tar alone does not install the entrypoint. Root owns the reviewed COPY assembly/config activation. No backend/JAR build is required. Compatibility and ordinary edit/Saved/reload/export/return acceptance remain browser work after actual artifact delivery; source review alone is not that evidence.

## First-use entry and return

The next source increment adds `studio_entry.cljs`, `auth.patch` and `entry-guide.patch`. The existing native auth page accepts only a validated 43-character `studio-connect` token on its login route. It stores an absolute same-native-origin `/studio-connect?challenge=…` continuation through the existing `:login-redirect` mechanism. The normal login consumer removes that entry and navigates via `rt/nav-raw :href`; no provider/session mechanism or automatic confirmation is added. The native connection page offers that explicit sign-in link and preserves both native proof and same-Studio-session final confirmation.

Studio challenge creation accepts only typed navigation fields (story, format, optional saved design, editor and page), with organization/brand taken from the currently authorized scope. It stores a canonical relative Studio task path; the native success link prefixes only the constructor-owned Studio origin. Page values follow the existing format bounds. These fields never grant file or brand access. Existing pending challenges without navigation retain their prior home return.

With the optional constructor origin enabled, native dashboard sections first show a concise Studio entry guide. Direct top-level entry links to the configured Studio host; inside the Studio frame it points to the already visible context-preserving return bar. A deliberate Personal or operator workspace disclosure retains the normal dashboard and its existing native permissions. Workspace/viewer/settings routes are unchanged; hiding a dashboard is not authorization. Without the constructor origin, normal native behavior is unchanged.

This increment changes the actual compiled native dependencies: pinned `frontend/src/app/main/ui.cljs`, `frontend/src/app/main/ui/auth.cljs`, the new entry component and the shared host module/test. It therefore needs an updated native frontend artifact, not just a Studio dist or gateway change. If the earlier candidate build is still queued, root may supersede it before execution after review; do not dispatch a duplicate build automatically.

The native runner requires explicit namespace registration in both its require list and `test-namespaces` vector. `runner.patch` adds this test namespace to both, so the focus command executes its real assertions. The earlier queued candidate compiled production/test code and passed thumbnail checks but rejected the unregistered new namespace; it is not a passing bridge-test receipt. Dashboard continuation uses the documented Rumext `children` slot so its fragment is compiled normally rather than returned as a raw prop vector.

Missing file/revision and outstanding changes retain guarded states. Runtime acceptance remains pending until the new frontend is adopted.
