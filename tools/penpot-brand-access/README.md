`PenpotBrandAccess` keeps a unique immutable native team for each Studio brand and separates `operatorProfileId` from the paired acting human. `registerWorkspace` accepts no browser IDs: its constructor-owned workspace is checked against actual `get-profile`, `get-project`, `get-team`, and `get-team-members`. Provider integration must supply a scope-bound **administrative workspace lookup** separately from acting-human authorization. The current founder-only story provider cannot be passed unchanged for a marketer. Keep the operator's existing design identity/hash and fonts immutable; do not replace its owner with each human. ## Exact native integration

Its exported `file-team`/`project-team` resolve native database ownership; `governed-team?` uses only a constructor-owned exact UUID set. `authorize-resource` passes authenticated native profile, DB-resolved team, operation and **actual** native middleware session to the constructor-owned current-authority callback. It returns `{governed:false,allowed:true}` for ungoverned teams regardless of Studio availability, leaving original native ACL in charge. Governed callback failure denies; a callback cannot relabel a governed team as personal. `assert-team!`/`assert-file!` are the resource guard helpers. There is no globally enabled deny-all unknown-command wrapper.

Hook the native file/project/team permission paths where ownership is known, before native owner/share/organization-owner fallbacks; keep original native ACL as an additional check. Aggregate listings require filtering only registered governed teams by current admission. Public sharing/invitation/member expansion/library publication and move/copy escape paths require exact governed-resource policy. Unknown ownership must not be called ungoverned. Preserve a reviewed separate personal/operator surface; do not activate an incomplete hook graph globally. C3's native subscription helper uses these same exported helpers and real session-manager identity. No native editing is accepted by this source checkpoint.

Install `studio_access.clj` as `backend/src/app/rpc/commands/studio_access.clj` and add `'app.rpc.commands.studio-access` to pinned `app.rpc/resolve-methods`' explicit `sv/scan-ns` list. It additionally requires a **separate** private 43-character grant key from the actual request header and a constructor-only current-intent authorization callback. No native owner/body alone can authorize it.

The command locks the actual operator owner and target member, rejects ordinary organization-owner fallback and administrative-owner replacement, then CASes a `studio-native-grant:<team>:<profile>` receipt in the existing `server_prop` table (`preload=false`). Same epoch/intent/present/operator replay is accepted only with exact actual membership readback. Older/mismatched epochs conflict. Membership and receipt commit together. Adding is UUID-only editor, never owner/admin; removal clears the exact team's file/project/team relations, preserving all files, edits, assets and other teams. There is no invitation email, new table, schema migration or native runtime action during preparation.

`PenpotBrandAccess.reconcile` persists the exact intent before the native call, keeps unknown results pending, and retries only the same key/payload. `authorizeReconciliation` validates actual operator/team/member/intent/epochs against current Studio membership and pairing. Positive native grants remain blocked until native policy and C3 are accepted; negative reconciliation can remove a revoked grant. `createPenpotMembershipReconciler` uses only the fixed native command, private operator session and separate grant key. Apply C2 before the separately reviewed C3 patch. Source-only preparation did not run this script or build/execute native code.

Explicit hosted namespaces: `app.studio.access-test`, `app.studio.http-authority-test`, `app.studio.reconciliation-test`. They exercise local governance classification and personal preservation, private fixed HTTP DTO/no-cookie/deadline/body bounds, epoch conflict/replay and exact native-role readback decisions. They are unit/compile checks, not proof that native SQL reconciliation or a real five-second fence works. Actual native DB/Neo acceptance remains necessary.

`app.studio.http-authority/create` uses the pinned existing `java-http-clj` 0.4.3 client, never redirects and calls only `http://host.docker.internal:39044/api/native/penpot/access/{admission,reconciliation}` with a private grant header. Its 1000ms total future deadline includes bounded 4096-byte response consumption; cancellation closes an observed or late stream. Configure it as the private `::access/authorize` and `::access/authorize-reconciliation` functions only through reviewed native constructor wiring. Node39044 forwards those exact paths to its fixed Studio loopback origin, preserving Studio's normal loopback Host/Origin boundary.

Admission DTO: `{nativeProfileId,nativeTeamId,operation,nativeSession:{id,profileId}}`. Reconciliation DTO: `{nativeOperatorProfileId,nativeTeamId,nativeMemberId,intentId,expectedEpoch,grantEpoch,present}`. Native cookies and JWTs never enter these bodies. The actual native session manager supplies/verifies `nativeSession`; governed admission accepts only an actual v1 UUID session ID before serialization. Legacy v0 string IDs can be cookie credentials and are denied without a callback; the user must sign in again. Personal legacy sessions stay on their unchanged native path; the websocket query UUID is not an authenticated session. C1's durable identity pairing alone cannot establish later Google JWT expiry from a digest; do not claim that it does. Current managed-provider checks and any explicit governed Studio lease semantics must be wired and qualified separately from native session expiry.
