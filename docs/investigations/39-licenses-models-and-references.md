Doory's [Attribution Assurance License](https://github.com/shaongitbd/doory/blob/27b6f68221fdbf1ef1bedc182e303210ca9e39f5/LICENSE) permits redistribution/use subject to conditions. Source redistribution requires prominent license text; binary distribution requires accompanying text and prominent launch-time author attribution. The text names the author's identity, role and repository URL and prohibits endorsement without permission. It also refers to GPG-signed text; how that condition is satisfied by the supplied plain license file remains an explicit upstream clarification item. GitHub reports `NOASSERTION`, not a recognized MIT identifier. Do not silently remove attribution for a white-label editor. Commercial permission is conditional, not an exemption from asset, dependency or model requirements.

## Doory's actual U²-Net weight chain

The pinned [model manifest](https://github.com/shaongitbd/doory/blob/27b6f68221fdbf1ef1bedc182e303210ca9e39f5/backend/data/ml_models.json) selects U2NetP by default, with a declared 4,574,861-byte ONNX file and SHA256 `309c8469258dda742793dce0ebea8e6dd393174f89934733ecc8b14c76f4ddd8`. Optional U2Net is 175,997,641 bytes with SHA256 `8d10d2f3bb75ae3b6d527c77944fc5e7dcd94b29809d47a739a7a728a912b491`. It supplies rembg download locations and pinned Hugging Face mirrors. These are manifest assertions, not independently measured binaries.

Independent text checks support part of that provenance: original [U-2-Net `ac7e1c817ecab7c7dff5ce6b1abba61cd213ff29`](https://github.com/xuebinqin/U-2-Net/tree/ac7e1c817ecab7c7dff5ce6b1abba61cd213ff29) has an Apache-2.0 license and README weight links; the [U2NetP mirror card](https://huggingface.co/BritishWerewolf/U-2-Netp/blob/7112208dbac3a3642496c8d54e2f0f9bb3dc1dc8/README.md) and [U2Net mirror card](https://huggingface.co/BritishWerewolf/U-2-Net/blob/c08042b462485d8597c89d3ce831d00be8582c5c/README.md) declare Apache-2.0. This does not prove mirror/rembg byte identity, conversion reproducibility, or complete training-data rights. The manifest's own “verified” statement is not our verification. Keep those items unresolved before managed distribution; do not substitute a different model under the same friendly engine name.

The [pinned worker](https://github.com/shaongitbd/doory/blob/27b6f68221fdbf1ef1bedc182e303210ca9e39f5/frontend/src/editor/engine/bgRemoval/worker.ts) processes image decoding, segmentation, matte refinement and PNG encoding off the editor's main thread. Its [model store](https://github.com/shaongitbd/doory/blob/27b6f68221fdbf1ef1bedc182e303210ca9e39f5/frontend/src/editor/engine/bgRemoval/modelStore.ts) fetches the selected model, checks expected size/SHA256 and caches it. Its [session](https://github.com/shaongitbd/doory/blob/27b6f68221fdbf1ef1bedc182e303210ca9e39f5/frontend/src/editor/engine/bgRemoval/session.ts) configures WASM and thread count. This is source evidence, not browser support or performance acceptance. Test worker/CSP, SIMD, cross-origin isolation where threading requires it, browser memory, cache eviction, cancellation and cold download behavior on supported machines. A “4.7MB model” is not the whole runtime download or peak-memory figure.

For IMG.LY separately, the [web README](https://github.com/imgly/background-removal-js/blob/12f56cc4f2a90d624e165a715748d22efc7a1d93/packages/web/README.md) documents default remote model/WASM downloads and browser caching, configurable `publicPath`, and model variants. Thus “in-browser” does not mean no network or no asset-hosting cost. No image upload by the segmentation primitive would not prove the whole editor, telemetry, error reporting or CDN request behavior is private. Verify network traces and storage policy in a real experiment. No weights were downloaded in this evidence slice; the runtime inference and binary-provenance experiment remains pending.
