# Bounded portable JSON accounting

Related to [#164](https://github.com/ChaiWithJai/liquidity-studio/issues/164). The earlier supervised and plain-entry512MiB candidate submissions failed; validity and exact kill-stage allocation remain unestablished. This source change does not claim maximum-pack acceptance or solve memory safety by arithmetic.

Pack size and content checksum now use one token traversal rather than whole-pack JSON.stringify allocations. Strings and keys are encoded in bounded4096 UTF-16-code-unit slices using standard JSON.stringify, with quote removal; a high/low surrogate pair is kept together across slice boundaries. Lone surrogates retain well-formed JSON escaping. UTF-8 byte accounting and SHA256 consume tokens directly. Both full-pack size and content checksum (excluding only the root sha256 field) preserve original object/integer/file property order. Global jsonDigest remains unchanged.

Accepted input is plain data. Arrays, finite numeric JSON semantics including negative zero, null/booleans, nested objects, ordinary undefined object omissions and array holes/undefined→null match standard JSON serialization. Accessors, toJSON, unsupported prototypes/symbol fields/functions/BigInt/nonfinite numbers and cycles fail explicitly before decoding/reservation. The existing48MiB byte and complexity ceilings, exact pack schema, checksum, canonical base64, file hashes, source validation and all pre-reservation transaction checks remain intact. No caller metadata is mutated.

Hosted differential regressions compare standard serialization/hashes across high/low/lone-surrogate chunk boundaries, Unicode/controls/escaping, integer/key order, numbers, shared nested objects, arrays and omissions. Real exported packs retain size/checksum and corruption rejection. Over-cap metadata refuses before base64 decoding or state writes; prior async validated-snapshot tests remain. No local Node tests or runtime replay ran for this change. Later ordinary Neo acceptance under reviewed resources remains necessary; no resource-cap or profile change is included.
