## Current content-work walkthrough

Updated for merged main `0f1c21d` (PR197/198/201). These steps describe the current controls. The founder path was exercised by engineers in the local developer profile, including both brands and real Penpot edits. It is not a completed learner assessment. Nicole’s paired marketer/native access is still pending; do not offer her someone else’s persona or credentials as a substitute.

1. **Choose your work.** Use your authorized workspace and brand, then open the story from the backlog. A Studio link retains its story, format and preview page across reload and browser Back/Forward. In the local developer application, choose the intended local persona if prompted; the link returns to the same task. This local selector is not Google sign-in or a production identity pairing.
2. **Prepare and inspect the copy.** If there is no saved campaign, choose **Prepare source preview** when available, then **Refresh preparation status**. A ready preview is still unreviewed. Read **Evidence and unresolved questions**, open the original source, and check dates, context and missing information. Use **Preview format** and **Page** to inspect all four formats. Edit the wording, choose **Save preview edits**, then reload to check that the saved wording is retained. A source excerpt is not automatically a complete conclusion.
3. **Review deliberately.** Choose **Review saved draft and evidence** only after saving. Inspect **All saved format copy**, select the correct content classification, and confirm only the review you actually performed. **Confirm reviewed copy and continue to handoff** saves that exact editorial copy. It does not approve a layout or publish. Clinical research keeps its separate current-founder clinical confirmation requirement; use a nonclinical example for this introductory lesson.
4. **See the work first.** In the saved campaign, choose the format above the artwork. The **Studio preview** is the saved Studio copy. Open **Preview settings** for phone width, zoom, safe zones, caption ruler and artifact details. The three frequent task actions are **Review sources**, **Edit wording** and **Preview & validation**. **Save artwork changes** appears when artwork is dirty. For reviewed prepared copy, use **Edit reviewed copy** to start the explicit new review path; do not expect direct edits to replace the reviewed generation silently.
5. **Choose the design path.** Where the configured Penpot feature is available, choose **Create design in Penpot**, then **Open design in Penpot**. Reopening returns to the same saved file. Edit a heading in Penpot, wait for **Saved**, reload that document, and check the text before returning to Studio. Penpot edits stay in Penpot: the Studio preview and **Export Studio preview PNG/ZIP/script** still use the saved Studio copy. **Edit layout in Studio** is a separate optional native editor when enabled, not a required step before Penpot. Do not infer that a disabled or absent editor has been provisioned.
6. **Find secondary actions.** Open **More actions** for **Validation results**, **Export handoff**, **Plan in calendar** and **Return to backlog**. In a keyboard lesson, open the disclosure, choose the action, and check that focus reaches the requested section. Completed source review is under **Review details**; **Linked design tools** contains the existing connection, update and history controls. Open these when needed rather than treating every panel as a step to complete.
7. **Leave a recoverable boundary.** Save, reload and reopen the same story/design. Unsaved edits block browser Back/Forward; save or explicitly discard them rather than navigating around the warning. Calendar placement sets a date, an export downloads an artifact, and neither publishes it. Native layout approval and verified-PNG signoff remain their own authorized workflow.

Observed product references: [PR197 create/edit/reopen and screen review](https://github.com/ChaiWithJai/liquidity-studio/pull/197), [PR198 compact task actions](https://github.com/ChaiWithJai/liquidity-studio/pull/198), and [PR201 preview-first layout](https://github.com/ChaiWithJai/liquidity-studio/pull/201). ## Readiness and learning objects

The trainer owns the opening context, objectives, prerequisite check and selected content (Gagné events1–4). Ask permission to record the session; choose a disposable authorized brand and avoid personal or clinical source material. Explain what is collected and where private records are retained. Declining recording does not bar practice. No learner names, recordings or performance records belong in the public repository.

These objectives are ordered to avoid a recovery lesson depending on material introduced only afterward. Work in short sessions: source preparation; native editing; review/export; recovery. Pause at a clean saved boundary. No numeric cognitive-load or quality score is assigned without evaluation.

## Worked example → explain → modify → independent practice

1. **Watch, with prediction.** Trainer selects an owned finance or cultural example, shows actual primary evidence and any limitations, reviews copy, then creates or reopens a Feed design using the available path above. Explain whether this is Penpot or the optional Studio native editor; do not imply an automatic two-editor sequence. Use a safe cultural excerpt (Yoga Sutra2.29 eight-limb description) or issuer-sourced Angel City transaction statement with current review. Do not substitute the quarantined Bhramari15× or neuroscience assertions. Record which source and exact saved candidate were used.
2. **Explain.** Learner describes the selected brand, immutable generation, editable native version, current approval and private asset ownership. Ask: “If I change the calendar date, which facts should change? If source copy changes, which approvals become stale?” Give feedback using the actual revision/readback, not a success slogan.
3. **Modify with guidance.** Learner edits a heading in a disposable design and saves/reloads in that same editor. Compare the Studio copy with the separate design so the learner can explain why they differ. Use a permitted palette refresh only where that editor’s explicit refresh path is available. If available, insert the already rights-declared synthetic portrait and use the reviewed MODNet processor. Preserve the original; explain the512KiB rejection rather than silently resizing. Compare saved text and pixels with the intended change. Stop if prerequisites are unavailable.
4. **Independent practice.** Learner repeats without step prompts on the other brand and a different format. Cover Feed, four-slide Carousel, Story and three-board Reel across the sessions. Trainer observes rather than operating the learner's controls. Capture actual elapsed time, errors, help and retries only with consent. A request for help is information for instruction, not a penalty.
5. **Feedback and retake.** For wrong scope, return to membership and opaque asset identity; for stale save, retain the local buffer and explicitly compare/reload; for unknown response, retain exact request/key and use the supported retry; for missing font/asset, stop and verify evidence rather than substitute silently. Offer another safe fixture and repeat only the failed skill. Record assistance and retake count honestly.
