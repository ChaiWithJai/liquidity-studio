# Catalog-bound NCBI EFetch clinical evidence

This backend increment follows the retained real PubMed HTML worker failures: each returned safe diagnostic HTTP 203 with content encoding absent. No response body or cause is inferred. The new route uses NCBI's documented machine-readable [EFetch service](https://www.ncbi.nlm.nih.gov/books/NBK25499/#chapter4.EFetch), not browser cookies, a challenge workaround or an automatic retry/fallback.

Only the three trusted clinical catalog pointers select provider `ncbi-efetch-pubmed-v1` and PMIDs 23439798, 21446363, 25535358. The retriever constructs exactly `https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi?db=pubmed&id=<one allowed PMID>&retmode=xml&tool=liquidity_studio`. No caller-defined host/path/database/query, email, key or signed-in identity is sent. HTTPS/public-DNS pinning/no redirects/200-only/identity encoding/512KiB raw body/8-second total bounds remain; 203 and 206 are rejected. A per-process queue serializes source requests with at least one second between starts, including abortable queue waits within the same deadline. This is not a distributed/IP-wide quota guarantee. NCBI's guidance recommends application/contact identification; this approved pilot sends the fixed tool name only and stays below the documented unauthenticated rate. No service key or per-user identity is introduced.

The installed Saxes 6 parser never resolves a DTD. It permits only the exact observed inert NLM 2025 PubmedArticleSet PUBLIC declaration, with no internal subset, ENTITY/custom entity, unknown public/system ID, stylesheet/other processing instruction or namespace substitution. Strict errors fail closed. Nesting, node/attribute/part/text sizes are bounded; exactly one PubmedArticle/MedlineCitation/Article/Abstract and exact PMID are required. OtherAbstract/reference metadata is not selected. Four unique structured Ashwagandha sections retain full text in source order; each other source requires its one reviewed unlabeled abstract. No selected text is truncated to fit a preview. Unknown/changed sections remain needs-attention.

Canonical `sourceUrl` remains the PubMed citation. `requestedUrl` truthfully records the fixed EFetch URL, with raw-response SHA/bytes/content type/time, typed provider/PMID, explicit XML extraction/selection version and policy digest. The portable prepared-history whitelist retains this metadata but imports no approval or execution grant. Current/build/fork/portable clinical guards bind transport, PMID, canonical URL, copy ID, clinical classification and dated publisher. Separate current-founder clinical confirmation is still mandatory; default copy remains observational, not breathing/dosing advice. Old nonclinical v1/v2/v3 projections and their historical URL behavior remain unchanged.

The checked-in XML is the actual complete three-record entity body observed by one bounded same-origin Neo fetch: HTTP 200, `text/xml; charset=UTF-8`, 37,580 bytes, SHA256 `329017aa127d8d6c83a57b18793d299554e86b29a3746773046acbc2cd75a08c`. Its provenance file distinguishes fetch body bytes from DOM serialization/compressed-wire capture and records that this was browser research, NOT worker acceptance. Hosted tests create controlled single-record envelopes from complete actual PubmedArticle blocks; positive abstract paragraphs are not invented. Tests cover exact copy offsets, full selected sections, malicious declarations/unknown entities, duplicate/wrong PMID/sections, HTML/size/depth, transport status 203/206, encoding/DNS, provenance tampering, portable historical authority and cancellation of queued requests. Existing tests retain old nonclinical/clinical confirmation coverage.

Adding a typed transport changes the three clinical preparation input fingerprints. Previously failed HTML jobs remain preserved; they must not be rewritten to pretend the old reviewed input was an EFetch request. Actual acceptance requires a newly reviewed job/ordinary Neo worker request for each clinical source after hosted checks and source review. There has been NO local test runner/build, worker request/retry, maintained migration, inference or provider call for this backend commit. Browser endpoint availability does not close the actual worker gap or approve the papers' clinical conclusions.
