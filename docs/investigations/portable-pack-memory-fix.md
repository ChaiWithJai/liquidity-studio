# Portable pack copy-lifetime correction

Related to [#164](https://github.com/ChaiWithJai/liquidity-studio/issues/164) and [#57](https://github.com/ChaiWithJai/liquidity-studio/issues/57). The observed frozen-baseline512MiB constrained import failed before a completed validation/reservation; candidate validity and exact kill-stage allocation remain unestablished. This change removes three avoidable copy/retention paths without changing pack/body/file/transaction limits or resource configuration.

Successful JSON body parsing clears incoming chunk references immediately after its single concatenation, before UTF-8 decode/parse. JSON hashing feeds the same ordered UTF-8 serialization directly to SHA256, avoiding a whole serialized Buffer. Pack validation keeps a detached metadata/container snapshot and new file records sharing only their already-validated immutable primitive values. Both top-level and file property order are retained, preserving exact checksum semantics. Import uses that validated snapshot before its first authorization await, preventing caller metadata mutation from replacing validated content during asynchronous authorization.

Source-auth/integrity/canonical-base64/size/transaction checks remain in place; caller input is not mutated. Hosted regressions cover Unicode and surrogate hashing, property order, bidirectional metadata/array/file-record detachment and mutation while authorization is held. No local Node tests or runtime acceptance were run for this change. A new ordinary Neo attempt under the same reviewed512MiB profile is a separate post-review gate; this source correction does not claim48MiB acceptance or memory safety by arithmetic.
