# Fresh cutout lineage through portable recovery

2026-10-18, issues [55](https://github.com/ChaiWithJai/liquidity-studio/issues/55) and [57](https://github.com/ChaiWithJai/liquidity-studio/issues/57). This actual BrowserOS Neo journey supplements the [durable native recovery checkpoint](../portable-recovery-neo/README.md). It closes the specific missing fresh cutout-lineage observation, not the whole recovery or media acceptance ticket.

## Actual inference and recovery

A separate owned SQLite fixture contained controlled current proposals for both brands in infographic and Reel formats. Its deterministic source campaign was administrative setup, not a claim of actual research or human approval. No cutout intent, output or processor event was seeded. The existing private licensed frame and exact local MODNet weights were reused without a build or model download.

The operator uploaded the existing generated 384×384 JPEG through the editor file input, declared `Owned generated synthetic portrait with no actual personal identity; cutout fixture.`, selected no personal data and explicitly confirmed the recorded rights permit removal. Clicking **Remove background** ran one actual local ORT WASM inference, approximately 20 seconds. The UI reported **Cutout ready. Review the result; Undo restores the original image.** The saved native proposal advanced to revision 4 and referenced the new derivative. No paid provider or campaign generation call occurred. The frame was then unmounted, disposing the worker before pack work.

Browser API readback recorded the exact original JPEG (34,832 bytes, SHA-256 `50db12119d03be4f4a2736586210f0eac990a667e7ea0d7a0d5469268dd93c5e`) and alpha PNG (198,985 bytes, SHA-256 `be20c97b37e61742d8fb60239df7f13fc3e14385b5b7fdbbb268c9fb228ac31d`), both 384×384. The output is deterministic and matches the older experiment's output bytes; this new observation has its own actual intent and actor, rather than relabeling an archived image as a fresh event.

After consistent backup and ordinary Operations export, the source database was retained offline. A different controlled owner in a separate SQLite database selected the pack, created a new empty destination and explicitly remapped owners through Operations. Reloading the page before installation preserved the recovery locator: status was **empty**, and the exact pack had to be reselected. No pack bytes or credentials were restored from browser storage.

The successful install preserved both exact image byte hashes. All 12 derivative lineage fields were unchanged: `kind`, `execution`, `serverValidation`, `inputAssetId`, `inputSha256`, `modelSha256`, `processorVersion`, `outputPolicy`, `documentId`, `nativeRevision`, `intentId`, and `actorId` (the exact complete lineage object is in the manifest). The historical inference actor differs from the current importing owner. Current asset ownership is remapped, while `portableHistory.sourceCreatedBy` and `restorations[].restoredBy` distinguish original action from recovery. The restored native revision 4 remains a proposal; no approval was installed.

Neo then re-ejected the restored scope through Operations. The resulting 2,865,313-byte pack, file SHA-256 `e32e8f111bca451089e69cfef1c77fb2a6fa9c5378154b5676d5fa349e456d80`, retained the exact input/output file hashes and the original full lineage. Browser readback and WebCrypto hashes are recorded in [manifest.json](manifest.json). A final consistent SQLite backup, including inline immutable assets, was 425,984 bytes, SHA-256 `2865e5226ba943ce5c37cec7f5415b2f390f2d6499fe7b4eee3792aea8e8a85f`, integrity `ok`, 16 records. Private database backups and complete packs are not published.

## Controlled fixture defect and explicit repair

The first install correctly refused **Orphaned generation lineage**. The fixture bootstrap had created a deterministic campaign with a generation ID but omitted its corresponding telemetry trace. The legitimate cutout operational record referenced that generation. This was an invalid controlled bootstrap, not evidence that ordinary production generation loses its trace.

The rejected pack, untouched original database, consistent backup and empty rejected destination were retained. With independent root review, an operational copy of the source database was repaired after verifying the controlled fixture marker and recomputing its exact `campaignFromApprovedClaims` campaign. Only two `telemetry.traces` entries were added, one for each controlled brand. No native, asset, cutout, source-approval or story field changed. The records explicitly say administrative repair, provider `none`, model `null`, model calls `0`, human review not observed, actual repair timestamp and unknown original execution time. They describe deterministic fixture campaign creation, separately from the one real browser inference.

The corrected bootstrap now records that deterministic fixture trace at creation. The repaired copy was exported again through Neo and installed with a new ordinary recovery intent/destination; no archive fingerprint, validator or production rule was bypassed. The original failed fixture remains available for the separate [145](https://github.com/ChaiWithJai/liquidity-studio/issues/145) fail-fast export check.

## Limits

Lineage execution remains explicitly `browser_reported`. Server validation verifies scoped source/native/input hash, rights, dimensions and output hash; it does not independently attest the kernel execution. This generated nonpersonal portrait is not a consenting-human quality benchmark. There was no repeated inference, audio, motion/video export, maximum-size memory experiment or commercial license clearance. The held upstream binary/source distribution boundary remains unchanged. Existing archived-pair evidence remains correctly described as incomplete; this new fresh event supplies its own complete lineage without rewriting the old experiment.
