## Bounded follow-up

The implementation deduplicates only raw managed-account lookup promises within two separate server-injected authority phases: resolve/authorize before official file ACL read, and a fresh resolve/authorize phase afterward. It never caches `authorizeJobActor` results. Every invocation still reads the current local principal/allowlist and compares the original approval timestamp against the provider record; membership, source, binding, image-generation and native ACL checks remain.

Each phase creates a new per-GoogleIdentity-instance asynchronous context, keyed by normalized email, and clears it on exit. A second phase and a different HTTP request always obtain a fresh provider record. Jobs outside these explicitly scoped media-read phases retain fresh lookups. Provider changes after the final lookup still have the ordinary authorization/response race; there is no claim of instantaneous revocation. No public asset exemption, internal-IP trust, shared operator cookie, global positive cache or resource lease is added.

Authored hosted regressions cover28 local checks with two provider lookups, concurrent-request isolation, provider disable/revocation between phases, local-principal and approval-time changes within a phase, provider failure, and no reuse by later requests or ordinary jobs. They have not been run locally under the Neo-only constraint. Exact-head CI, actual repeated timing and actual native pixels remain separate gates. Cultural image coverage and independent archive/image/font recovery remain open, as does standalone SVG resource embedding.

## Separate SVG compatibility proposal

The pinned [SVG exporter](https://github.com/penpot/penpot/blob/ff7a66f51938b2293260ea27a64e2c4e0833b5e3/exporter/src/app/renderer/svg.cljs) sends `render-embed=true`. The pinned [render entry point](https://github.com/penpot/penpot/blob/ff7a66f51938b2293260ea27a64e2c4e0833b5e3/frontend/src/app/render.cljs) parses raw query parameters, declares `embed`, and passes that value to the [native render provider](https://github.com/penpot/penpot/blob/ff7a66f51938b2293260ea27a64e2c4e0833b5e3/frontend/src/app/main/render.cljs). There is no alias in that inspected path. Actual prior SVG downloads retained protected image/font URLs.

The optional owned ingress therefore prepares an exact `/render.html` compatibility location. Only the observed canonical one-file/page/object SVG query receives `embed=true`; every existing file/page/object argument is retained. Its strict full-query match excludes duplicate, encoded and unknown argument forms. The exact original-query match excludes the redirected query with its appended `embed=true`, preventing a loop. Location-scoped [`absolute_redirect off`](https://nginx.org/en/docs/http/ngx_http_core_module.html#absolute_redirect) ensures nginx leaves the302 Location relative, retaining the caller's public or internal origin and port. That relative302 keeps the browser on the same owned origin and changes the query visible to `location.search`. The unchanged upstream HTML is served; no asset ACL, native cookie, upstream image, renderer code or public exception changes. The complete actual nginx main plus this overlay passed syntax validation without reload. The first4415 trial used an internal rewrite and failed: the actual7805-byte SVG was unchanged (SHA256 `08899b8cc430049f0b5d263c1da3bfdd078ee5eb5012fe7d4afd114274b63d37`), with six text elements and three protected resource URLs. Resource Referer headers retained the original browser query. The frontend was rolled back before callback stop. The corrected redirect remains a separate unrolled change: actual SVG data-URI image/font presence, absence of protected external URLs and visual fidelity must be observed before any portable SVG claim.
