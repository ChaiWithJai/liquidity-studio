Reviewed private design is the source of requirements; this public source spec contains no actual private claim or dataset. Separate from frozen PR363 and its authored earnings control.

Implement a pure version2 historical-store-period-comparability case pack. Existing earnings/version1 factory and runtime behavior stay unchanged. Constructor owns bounded pinned pack bytes plus answer/snapshot/state loaders and current authorization callback. Only caseId comes from the coordinator. Before/after every asynchronous load and before returning, verify current authority; validate exact generation-bound bytes through loader composition, then SHA/size/fatal UTF8 here. No network or filesystem implementation, arbitrary URLs, historical JavaScript execution, current-snapshot substitution or model request in this module.

Pack has exactly one observed-answer typed case with answer hash/size/exact code-point quote, historical snapshot hash/size and revision, neutral state hash/size, finite coverage/comparison selectors and reviewed historical normalizer Git blob. State contains only claim and neutral historical evidence. Independently server-load answer<=64KiB, snapshot<=4MiB and state<=12000B; quote must exactly reproduce both case claim and state claim. Validate unique store coverage/comparison/group link, exact declared month lists and source references, twelve-or-fewer ordered observations per side bound, valid dates and nonnegative row counts. Compare exact neutral fields against historical snapshot plus fixed contemporaneous interpretation. Legacy false is preserved without introducing later correction or semantic expected label. Missing/mismatched data is unavailable or rejected before provider work, never a semantic fail/pass judgment.

Return the existing finite ref/state/deterministic contract plus explicit provenance and new deterministic version. Provider evidence is serialized string<=12000B, claim<=4096B. Mechanical pass means pinned input eligibility only. No earnings numeric coercion. Future coordinator must bind resolver version and provenance/configuration in replay and persisted record; existing hardcoded earnings version cannot silently be reused. The separately specified variant integration below extends runtime configuration and saved-result provenance without changing363; actual publication/adoption and experiment execution remain gated.
