# Served evidence coverage and discovery

## Objective and boundary
Provide a deterministic bronze-oriented discovery view from facts already retained in the authorized normalized evidence snapshot. Name the result **served evidence coverage**, not a complete bronze inventory. No bucket listing, archive parsing, new data ingestion, model, embedding call, source fetch or write is part of this slice. Missing facts remain missing.

## Source contract and integration proposal
`discoverServedEvidenceCoverage(normalizedSnapshot, {query?,fromMonth?,toMonth?,offset?,limit?})` is an internal pure projection. It is NOT an authorization boundary or a mounted API. Proposed integration is one finite resource inside the existing evidence service after its current authorize→load→normalize→authorize→revision checks. The implemented finite resource is GET `/api/studio/defiant-evidence/:organizationId/coverage`, with the same scoped service and current revision. MCP `defiant_discover_served_evidence` exposes strict equivalent inputs. No UI integration is changed.

The projection groups exact source hashes referenced by retained earnings periods, receipt examples, aggregate selections, comparison references and audience worksheet references. It returns source hash, reference kinds, observed member names, explicitly supplied source-system/account context, retained labels, earnings months/currencies, typed reference counts, and missing metadata fields. Counts of selection record references may overlap; they are never original file row counts. Member names are source-receipt metadata, not filesystem access paths. No receipt cell values enter the text index or output.

Text matching is case-insensitive NFC-normalized substring matching on those retained metadata fields and source hash. Query≤200 characters; period inputs are valid YYYY-MM, inclusive bounds. A period filter excludes undated references and explicitly reports their presence. Hash ordering and offset pagination are deterministic; page1–100, offset0–5000. Scope/revision and existing producer coverage text are retained. Unreferenced input inventory arrays are ignored; complete inventory remains false even for an empty result.

## Optional embedding-index interface: design only
A future separately permitted index adapter would accept `{schemaVersion:1,snapshotRevision,sourceHashes,metadataProjectionVersion:1,indexVersion,modelId,dimensions}`. It must bind exact source membership/revision and approved metadata projection, with explicit provider/cost/retention authorization before any embedding creation or query. Stale/missing indexes must report unavailable, not silently generate or substitute semantic ranking. This proposal defines no model, vector store, dependency, executable adapter, or hosted route. Current discovery remains deterministic substring matching only.

## Plan and hosted validation
Three disjoint files: pure projection, focused Node contracts, this specification. Authored contracts cover source-hash dedupe, overlapping references, exclusion of unserved inventory/raw cells, deterministic query/period/page behavior, undated/missing fields, input bounds, malformed snapshots and nonmutation. Execution is solely future normal hosted Verify (`node --test server/defiant-evidence-discovery.test.js`); no local build/install/test/model work. Source review precedes any integration/push; actual private read acceptance remains separate.

## Bounded projection and integration contracts
Metadata arrays cap members/labels/systems/accounts at five each, periods at24 and currencies per period at five. Every bounded array reports total/returned/omitted counts. Matching examines all retained metadata before projection, so omitted labels and periods remain discoverable. UTF-8 JSON response size is capped at3MiB, below the private bridge4MiB limit; no silent truncation of source membership. Authored Unicode100-source contracts exercise the maximum page and an omitted-field match. HTTP rejects duplicate/unknown/overlong fields; service rejects coverage-only fields on other resources before loading. SDK/HTTP contracts prove equal normalized scope/revision DTOs, stale revision and wrong-scope/current-revocation denial.
