# Selected-record reconciliation

Status: authorized source implementation; no deployment or runtime acceptance. This extends the evidence service with a typed record of previously reviewed selected-cell arithmetic. It does not recompute cells at request time.

## Contract and plan
Optional `selectionReconciliations` preserves normalized legacy bytes when absent. When present it is an array of at most2000 records and1MiB of UTF8 JSON. Each record has exactly schemaVersion:1, method:`selected-derived-cells-signed-decimal-v1`, selectionId, sourceHash, currency, metric:`source-total-earned`, month, selectedRecordCount, selectionRecordSetSha256, declaredAmount, recomputedAmount, positiveAmount, negativeAmount, zeroRows, predicates and provenance.

Predicates have exactly sourceSongId/store, bounded500UTF8bytes each, exact raw strings. They describe equality against fixed source columns `TC Song ID` and `Store Name`; no expressions, title joins or arbitrary columns. Month is retained producer group metadata, not inferred from labels; response periodQualification explicitly states it is not independently established by this read. Provenance has exactly crossTabSha256, selectedReceiptsSha256, producerReceiptSha256, independentReviewSha256. These are retained artifact identities, not cryptographic reviewer certification. No source generation, identities, paths or timestamps are fabricated.

The normalizer checks one existing selection per record; exact source/currency/count and declared amount; SHA256 of UTF8 compact JSON of ordered record integers; recomputed amount equals declared; positive+negative equals recomputed; signs; and0<=zeroRows<=count. Decimal operands allow optional minus,1–26 integer digits with no redundant leading zeros, optional1–12 fractional digits. Use strict end and scaled BigInt, not floats. Missing positive/negative row counts remain absent. However count minus zeroRows must support every nonzero sign bucket, and zero sign totals require all rows to be zero; reject impossible metadata without inventing individual sign counts. Duplicate selection IDs, malformed proofs and unknown fields fail closed. Locator arrays are existing strictly increasing unique logical CSV record numbers>=2 (header is record1), never silently sorted/deduplicated.

Finite `selection-reconciliation` read requires selectionId+current revision; no pagination/extra filters. Missing selection404; existing selection without proof returns available:false/reason:not-prepared. Available response always declares rowConvention:`1-based-logical-csv-record-including-header`. Available response distinguishes runtimeBinding:`checked` (metadata binding/arithmetic only) from retainedDerivedReview:`reported-pass` (producer-supplied retained review of selected derived records). It exposes source-local predicates and fixed columns, current revision, review provenance, limitations and receipt paging follow-up. No full-source/provider completeness, settlement maturity, causal, rights, economic correctness, identity equivalence, model quality or whole-answer correctness claim. An example invented selection may declare2.50 USD with3.00 positive/-0.50 negative,2records/0zeroRows; this is illustrative, never production data.

Reuse current service authorization-before-validation, post-snapshot membership and revision guards, existing HTTP parser, MCP registration and fixed private bridge map. No new authority, endpoint mounting, MCP writes or runtime config. Optional manifest proof count is discoverable only when field exists. Same snapshot revision includes proof fields; input provenance never references the new snapshot itself.
