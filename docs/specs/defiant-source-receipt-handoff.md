# Exact retained-source to original-receipt handoff

## Problem and scope
Semantic retained-source results currently lead only to another metadata card. A referenced-by-served-evidence label does not provide a usable receipt path. Implement an exact-hash reverse lookup over existing normalized products, then normal Studio receipt navigation. No new embeddings, source scans, dataset, financial inference or arbitrary object reads. Manual matching is not completion of this workflow.

## Finite read contract
Add read-only `source-evidence` resource with required `sourceHash` (64 lowercase hex) and exact current `revision`; optional `offset` (integer0–24400 under the explicit API cap), `limit` (1–100, default25). Existing normal, local-grant and remote evidence authority applies before and after snapshot load. Validate hash membership in the current normalized retained register roots or members before enumerating products. Missing register returns availability:false/reason:register-unavailable and no zero-inventory claim; hash not in register returns404. Wrong/stale revision409. Source hash is content identity, not a chosen occurrence: return exact occurrenceCount plus a typed existing retained-sources hash-filter follow-up with offset0/limit25; do not embed an unbounded occurrence-ID array, and never pretend duplicates identify distinct financial rows.

Enumerate finite existing product types: `selection` from snapshot.selections where sourceHash equals requested hash; `receipt-example` from snapshot.receipts with the same exact hash. Also include `earnings-period` from snapshot.months with exact sourceHash, and `audience-definition` from audienceDefinitions with exact sourceHash. Include `comparison-example` for existing comparison group sourceReferences whose sourceHash matches, retaining comparisonId/groupId/referenceIndex (never claiming full-group receipts). Each row contains kind, stable product ID, sourceHash, currency and existing amount/metric qualification only where those fields actually exist. Do not manufacture a receipt total, period or metric from filenames. Stable order: kind then exact ID. Page unified references, not source rows. Bound metadata lengths using the existing normalized schema. Return total matching references/nextOffset, plus counts by type. Existing selections and receipt examples can overlap; totals are navigation-reference counts, never financial row counts. Do not load original cells for this lookup.

Each selection row has a typed existing follow-up `{resource:'selection',selectionId,revision}` and original-cell follow-up `{resource:'selection-receipts',selectionId,revision,offset:0,limit:25}`. Each receipt example has `{resource:'receipt',receiptId,revision}`. No synthesized product IDs. Stable page keys for earnings use the tuple kind/month/currency/sourceHash; comparison examples use kind/comparisonId/groupId/referenceIndex; all other keys use kind/product ID. An earnings-period follows existing `earnings` with month/currency/revision, showing the selected exact hash and rejecting a mismatched response. It may expose only the actual normalized row's receipt references, never infer completeness or synthesize IDs; the separate same-hash receipt-example rows remain available. Audience follows `audience-definition` then `audience-cells` with audienceId/revision, retaining worksheet sheet/cell references and their qualification. Comparison example follows existing `comparison-examples` with comparisonId/groupId/referenceIndex/revision, explicitly examples-only. A source may have zero supported original-cell references; explicitly state `no-supported-evidence-reference` rather than claiming no source data. Association alone is never proof cells can currently load. Existing downstream loader errors remain errors.

Expose the finite resource through normal evidence HTTP and existing explicit MCP/stdio allowlists (one new read tool, consistent schemas/inventory). No writes, broad parameter passthrough or model invocation.

## Navigation and return
Keep retained mode and its existing semantic sessionId, semantic page offset, original filters and revision intact. Add addressable source-reference state (exact selected source hash and reference-page offset) rather than clearing the semantic session or replacing original filters. The source-reference panel displays exact hash, duplicate-occurrence qualification and bounded product links. Opening a selection/original receipt carries a validated return trail containing the prior retained mode/session/filter/page/revision and source-reference page. No nested arbitrary URL. Back restores that exact trail without another semantic start; reload retains it. Existing account/org epoch fences and revision validation remain mandatory. If underlying revision changes, fail stale and ask refresh; do not silently reinterpret a saved session.

Use existing selection, earnings, receipt, comparison-example and worksheet renderers for original cells, with source hash/locator/currency/amount/revision visible. Preserve original receipt paging. The return trail must survive this paging and reload. Missing register, no supported reference, load failure, stale scope and busy states are distinct and accessible. Keep controls usable at390px with physical Tab focus. This is a direct product handoff, not a claim that embeddings indexed financial cells.
