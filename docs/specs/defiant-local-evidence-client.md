## Runtime reads and bounded renewal

Normal stdio startup consumes only the version2 scoped-grant envelope. The existing Firebase bearer-envelope mode must not remain an accidental fallback. Recheck current config and file owner/modes, strict org/syntax/expiry before every request. Evidence GET uses only the scoped ea access token; the existing HTTP route checks current maintained identity/UID/membership before and after asynchronous evidence work.

If access expiry is within30seconds, run one renewal through POST renew at the same canonical origin and configured org. Renew only on demand, at most once for that read; never run a background timer. One in-process single-flight promise shares the result among concurrent tools. Use an exclusive owner0600 sibling lock for cross-process coordination; a contender waits briefly then rereads the atomically updated envelope, never sends the same renewal token concurrently. Never automatically steal a stale lock: fail closed with a safe recovery message. After acquiring lock, reread config/envelope and verify the file identity/content still matches the expected renewal generation before submitting. A successful renewal must preserve the exact original absolute expiry and org, rotate both credentials, and retain the same grant ID. Atomically replace the envelope and release the lock in finally.

If renewal succeeds remotely but local durable write fails, the old renewal token has already been consumed. Fail closed and require explicit pairing recovery; do not replay it or imply the old credential remains usable. If any HTTP response is lost, do not automatically repeat renewal. Grant revocation/provider revocation/current membership denial must not trigger login, pairing, new credential acquisition or evidence replay. An evidence GET is never retried automatically; the user/host may make a later explicit tool call.

All pairing/token responses must retain the server's existing `Cache-Control:no-store`; client fetch uses cache:no-store, credentials:omit and redirect:error. General Studio authentication continues to reject ea/er tokens. Raw renewal credentials are only accepted by the finite renewal endpoint, never evidence GET or approval routes.
