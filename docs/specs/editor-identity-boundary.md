# Editor identity and private asset boundary (#52)

This optional boundary is local application engineering. It does not provision editors, credentials, buckets or cloud resources. It enforces Studio authorization before a registered adapter is called. Native Doory/Penpot permission enforcement, comments, WebSocket behavior and S3/GCS client interoperability still need separate actual adapter acceptance; an injected test port is not evidence of those capabilities.

## Authority and registration

STUDIO_EDITOR_BOUNDARY_ENABLED defaults false. An operator supplies STUDIO_EDITOR_TARGETS_JSON (default empty), or the equivalent trusted createPlatform editorTargets constructor argument. Each target fixes id, organizationId, brandId, adapter, ownerPrincipal, nativeProjectId, nativeRoomId, nativeDocumentVersion, nativeVersionKind, editorVersion and resources. Each resource has a logical id, kind, nativeId and nativeParentId equal to the registered project. Supported targets are DooryDocument1 at source27b6f68221fdbf1ef1bedc182e303210ca9e39f5, and Penpot2.18.3/archive1. nativeVersionKind must be archive for Penpot or document-schema for Doory. These are registry version boundaries, not native schema equivalence. Operator configuration must be established from actual owner-scoped editor setup; this module does not remotely verify ownership or fabricate a native project.

Authenticated founder registration POST /api/studio/editor-bindings accepts only {targetId}. It cannot introduce an external principal, URL, room or document ID. Marketers can use existing bindings only while they retain current organization/brand membership. The external ownerPrincipal differs from the Studio actor ID. UI preset names, document plugin metadata and caller-supplied native IDs have no authority. A changed target configuration invalidates existing bindings until founder registration. GET lists live bindings; POST /:bindingId/revoke increments the epoch and revokes access, preserving Studio originals.

Targets and grant hashes are stored under editor-security:organizationId:brandId, outside scope:* data. Existing portable export/import does not export these records or grant access on restore. An operator must explicitly remap and register restored external identities. No credential is accepted in the target registry. No shared bucket becomes public, no HMAC key is created, and no URL is interpreted or fetched here.

## Operations and adapter interface

All paths retain the existing authenticated organizationId/brandId query scope. POST /:bindingId/operations accepts {resourceId,kind,action,command?}. Kinds cover document, tokens, comment, room, cache, artifact and recovery. The server resolves native IDs from its binding, applies allowed actions and reauthorizes current membership before the adapter and after completion. Cache keys include organization, brand, binding, epoch, kind and logical resource ID. A default unconfigured transport rejects501.

A trusted injected transport implements validateCommand({binding,resource,action,command}) and execute({binding,resource,actor,action,command,cacheKey,reauthorize}). Its validator must strictly bound the adapter-specific native schema/bytes/revision and reject endpoint/credential/identity overrides. Only its validated return reaches execute. The caller never chooses a transport URL. This boundary does not grant permission to create new external resources: initial native creation and ownership verification are operator setup; a future provisioning slot needs an explicit trusted mapping transaction. Existing #53/#54 pure compilers remain separate. Event/callback state belongs to #56 and is not duplicated here.

Direct join operations are denied. POST /:bindingId/room-grants accepts {resourceId,ttlSeconds?}; POST /:bindingId/room-join accepts {token}. Grants are actor-bound, stored only as SHA256, valid1–300seconds (default60), epoch-bound and consumed atomically once. Current membership and binding revocation are checked at consumption. These tests prove the Studio admission gate, not an actual native WebSocket join. Authenticated callbacks and public-share routes reject403. No anonymous callback bypass, external signing secret or public share is enabled.

## Private assets

POST /:bindingId/asset-grants accepts {assetId,expectedGenerationId,expectedSha256,ttlSeconds?}. It obtains bytes through the existing scoped repository (including its GCS adapter where configured), verifies stored owner scope, generation, SHA256, MIME and size. Allowed MIME types are PNG/JPEG/WebP/ZIP and UTF8 plain text; bytes must be nonempty and at most20MiB. It returns an owner-scoped manifest, opaque short-lived token and explicit publicShare:false. It never returns GCS credentials, public object URLs or portable authorization.

GET /:bindingId/asset-delivery requires normal Studio authentication plus X-Editor-Asset-Grant. It reauthorizes the actor/binding, atomically consumes the matching grant, rereads and rehashes the asset, rechecks membership/revocation and returns attachment bytes with private,no-store. An invalid or failed read consumes an otherwise valid grant: request a new grant rather than replay. Tokens must not be placed in native documents or query URLs. No CORS, HMAC, S3-signature or external editor asset client compatibility is asserted. Browser/native clients must separately prove secure delivery without exposing shared credentials.

## Verification and rollback

Run `cd liquidity-studio && node --test server/editor-boundary.test.js` and then `node --test server/*.test.js` on Node22. Actual ephemeral HTTP tests cover founder/marketer, two brands and a third organization with the same preset; forged owner/project/resource/scope; resource-specific calls; distinct cache keys; live membership removal; collaboration actor mismatch/expiry/replay/revocation; real private attachment bytes, foreign asset/generation/checksum rejection; portable scope remap without editor access; operator URL/credential rejection; changed registry and default transport fail-closed behavior. Native resource operations use an explicitly labeled in-process test transport, not external comments/collaboration proof.

Rollback disables the feature and/or revokes bindings. Preserve security journals and original Studio data; do not delete portable drafts to revoke integration access. Remaining acceptance: actual per-client S3/GCS interoperability, external transport/owner handshake and true native end-to-end authorization, callbacks and full cross-editor recovery. #52 is not closed by these foundation tests alone.

The boundary rechecks live membership and binding epoch after asynchronous command validation, immediately before dispatch. Transports receive a reauthorize callback and must call it before each remote side effect, enforce native revision preconditions and handle disconnect/revocation. An external write already accepted cannot be undone by a later authorization failure; no instantaneous remote revocation guarantee is claimed.

## Studio-owned native image contexts

The native host has a separate, original-owned same-origin asset client. `POST /api/studio/native-editor/assets/:id/resolve` accepts an explicit `library-preview` or `document-usage` intent, captured native document ID/revision and generation ID. Both resolve the document and current source server-side, check membership before and after payload retrieval, and reject context drift. Document usage additionally requires the asset in the saved document's validated references. Library preview deliberately permits an owned brand image not yet inserted/saved; it is not authority to save that image into another scope.

The versioned response manifest separates immutable brand-upload identity/hash/MIME/size/dimensions from this document/generation usage. Upload ownership is not rewritten to claim the image was generated with that campaign. Parent broker chooses the intent from the saved native document and supplies its captured context; the frame cannot override that context. Existing scoped library/upload routes remain compatible, with normal membership enforcement. No storage reference, credentials or GCS object generation is exposed to the browser.

Delivery uses authenticated Studio JSON bytes and verified editor-session Blob URLs, not direct S3/GCS URLs. Session expiry/current membership is checked on each retrieval; scope/frame disposal revokes Blob URLs. Already delivered pixels cannot be remotely erased, and a cached image is not a renewable authorization grant. The independent binding-grant API still provides its explicit short-lived, single-use delivery semantics. This change does not assert actual cloud client acceptance, public distribution clearance, comments, multiplayer or external-room support.
