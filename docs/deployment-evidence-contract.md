# Pilot deployment evidence contract

`scripts/gcp-pilot.mjs` imports the pure validation helpers before it can reach a mutating gcloud command. Only the explicitly selected project, `us-east4` region and positive budget at most USD100 are accepted. Service/database/bucket identifiers cannot add comma-separated environment variables. Images must use an immutable digest in that project's us-east4 Artifact Registry.

Deploy/rollback require `--apply`, an existing JSON `PILOT_ACCEPTANCE_REPORT` no larger than one MiB, an explicit billing account and budget ID. The report includes `project`, `region`, `image`, the40-character tested `commit`, a recent ISO `generatedAt` and `checks` with `docker`, `browser`, `isolation`, `restore` each `passed`. Optional `PILOT_TESTED_COMMIT` pins the reported source revision to a separately known build revision. Generate the report from actual evidence and retain logs; JSON validation does not authenticate a self-written assertion or prove a cloud deployment.

The script verifies an active accessible project, its configured billing account, exact budget resource identity and project-number scope. The budget must be monthly, positive USD, all services, with an enabled current-spend alert destination. Alerts remain notifications rather than guaranteed hard caps. Deployment also verifies Firestore Native and private GCS resources in the approved region/project. Bucket description uses `--raw` to validate the actual API's camelCase metadata; public-access prevention and uniform bucket access must be enforced. Service-wide `--max=1` supplements the revision limit so a candidate and prior revision cannot independently bypass the configured service maximum. Platform limits still do not bound all downstream charges.

Rollback validates the referenced revision's actual image against its acceptance report before traffic movement. It does not restore data, revoke a candidate tag or reverse schema changes; the separate reviewed recovery contract still applies. This script creates no prerequisites automatically and exits on authentication or inventory failures before deploying. No real gcloud apply was executed during this change.

Verification: `node --test scripts/gcp-validation.test.mjs scripts/gcp-plan.test.mjs scripts/gcp-apply.test.mjs`. The apply tests use an isolated fake gcloud executable and verify blocked paths produce no mutation; they are not live-cloud evidence. The helpers' budget fields follow the [official Budget API](https://cloud.google.com/billing/docs/reference/budget/rest/v1/billingAccounts.budgets); raw bucket metadata follows the [official CLI reference](https://docs.cloud.google.com/sdk/gcloud/reference/storage/buckets/describe).
