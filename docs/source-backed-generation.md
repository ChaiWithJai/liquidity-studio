# Source-backed generation

Generation now requires `story.sourceClaims`: an array of reviewed `{id, text, sourceUrl, status, kind}` claims. Kind must be explicitly classified as financial, cultural, clinical or general; missing classification cannot approve a claim. Authorized editorial reviewers own classification, and no automatic classifier certifies truth. Only `approved` claims with HTTPS source URLs are eligible. Bare legacy `verifiedFacts` are not evidence and no longer enable generation. Source URLs and approval record editorial review, not automated truth. Clinical claims use `kind: clinical` and remain quarantined until `clinicalReview: {reviewerId, reviewedAt}` is recorded by the authorized review workflow.

The initial release uses controlled source excerpts in all four formats. Models must return the prescribed neutral template and exact source text. Output that changes a number's units, introduces a causal/medical/financial assertion or relabels revenue as margin is rejected before persistence. This deliberate restriction trades creative phrasing for auditable semantics; changing that contract requires source-linked editorial review, not a numeric regex. Human edits can be evaluated against the same contract and require review when they depart from it.

`evaluateCampaign(campaign, story, brandProfile)` measures source-excerpt contract coverage for the brand's content domain. It returns `factualAccuracy: not_assessed`, an explicit score meaning and required editorial review. A score of 100 does not certify source quality, financial truth or clinical efficacy. The CWJ preset preserves founder-supplied identity, tagline, palette/fonts/monogram, four proposed audience groups and five editorial pillars. Audience positioning is not scientific evidence. Its five research tasks remain unreviewed with no source claims or verified statistics. Story titles are never copied into generated assertions; generated headings are neutral. Presets never grant access.

Provider configuration supports `gcp-gemini`, `gcp-vertex` and `openai-gateway`. Gemini uses `GEMINI_API_KEY`/`GOOGLE_API_KEY` in a header, not a logged query. Vertex uses its documented OpenAI-compatible endpoint and a fresh injected access-token resolver, `GOOGLE_OAUTH_ACCESS_TOKEN`, or opt-in `AI_VERTEX_USE_METADATA=true` for the attached service identity; explicit project/location are required. An injected resolver is preferred for long-lived non-GCP processes because a static OAuth token expires. No automatic model failover or implicit paid retries occur. Model access and quota must be validated with an approved bounded live probe before claiming provider readiness.

Official references checked on 2026-10-17: [Gemini generateContent](https://ai.google.dev/api/generate-content), [Vertex OpenAI compatibility](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/model-reference/inference). Tests mock provider transport and assert endpoint/auth/payload contracts; no paid provider call was made. Provider calls have a configurable 10ms–60s deadline, response-size bound, output-token cap, redirected requests disabled and redacted error codes. Synthetic mode still requires explicit opt-in and is marked degraded, including the reason and source claim IDs. Source/clinical review failures cannot fall back to synthetic output.

Run `node --test server/gateway.test.js` from liquidity-studio. Existing HTTP/QA fixtures must explicitly supply reviewed test claims; production source approval is an authenticated workflow owned by the backend. Integration must pass before merging because unreviewed legacy seed stories intentionally stop generating.

Rollback is an application revert with no storage migration in this change. Reverting reintroduces weaker source checks, so preserve sourceClaims and review metadata in storage and do not downgrade silently. The running local port-3000 service is untouched.
