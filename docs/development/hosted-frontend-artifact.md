# Build the frontend before opening a PR

When local builds are unavailable, use the manual **Canonical frontend artifact** workflow to assemble the same `NODE_ENV=production npm run build` output as Verify. This workflow builds only. It does not replace any required check or deploy an application.

1. Commit and push the source branch before opening its PR. Record the full commit SHA.
2. Dispatch `canonical-frontend-artifact.yml` from main with `source_sha` set to that exact SHA. For example: `gh workflow run canonical-frontend-artifact.yml --ref main -f source_sha=FULL_COMMIT_SHA`.
3. Require a successful run. Download its `canonical-frontend-FULL_COMMIT_SHA` artifact. Verify `provenance.json` identifies the requested SHA and compare the checked-out source/dependency inputs with its source-file inventory. Verify every output size and SHA256 before copying `dist/` into `liquidity-studio/dist/`. Reject unsafe archive paths or symlinks. Remove obsolete tracked output files; do not edit generated bytes.
4. Commit the exact output and retain the artifact/run provenance. Open the PR. All five existing Verify checks must pass on that final PR head, including the canonical `dist` comparison.

A source update to an already open PR can still start Verify immediately. This workflow does not skip or cancel it. If build inputs change after the artifact run, obtain a new exact-source artifact before final checks. A test-only change can retain the artifact when its frontend/build/dependency inputs are demonstrably unchanged.

This shortens the normal source-first delivery path to one build-only run followed by one full required suite. It leaves `.github/workflows/verify.yml` unchanged. Related delivery work: #12 and #195.
