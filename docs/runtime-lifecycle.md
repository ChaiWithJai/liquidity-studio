# Node server lifecycle

The current Node 22 entrypoint is `node server/index.js` (`npm start` from liquidity-studio). PORT defaults to 3000 for a direct process; the local container uses 8080 internally and maps a separate loopback port. An occupied configured port exits 1 with `startup_failed`; it never silently selects another listener. The HTTP listener binds all interfaces inside its environment, while Compose binds the host mapping to loopback.

SIGTERM and SIGINT stop accepting connections and drain in-flight HTTP requests for up to ten seconds. Successful drain exits 0; the deadline destroys remaining HTTP connections and exits 1 with `shutdown_timeout`. Idle keepalive connections close, including connections that become idle after a response. Repeated signals do not extend the deadline. Compose allows fifteen seconds before forced termination.

Durable writes complete before their HTTP success response. SQLite commits use transactions/WAL on the persistent volume; Firestore operations are awaited before response completion. HTTP draining does not turn unfinished background work into completed work. Weekly job state records running/completed/failed/interrupted outcomes and an expiring lease; a later explicit run can inspect partial progress. The worker CLI closes its store on normal completion and exits nonzero on failure.

`/healthz` is process liveness and does not wait for dependency initialization. `/readyz` has a bounded dependency check and reports provider connectivity as not_checked. Cloud mode includes Firestore/GCS availability. Initializing or broken dependencies can therefore produce live but not-ready responses without leaking connection strings or provider errors.

Run `node --test server/runtime.test.js` from liquidity-studio. Child-process tests use ephemeral loopback ports for occupied-port failure, both signals with active requests, and a stalled request hitting the deadline. Operational and platform tests cover dependency errors, bounded readiness, async persistence and sanitized JSON failures. Local Docker acceptance additionally recreates a real container and verifies persisted drafts, calendar and downloadable assets. None of these tests operates the existing port-3000 process.

The earlier issue #11 slice deferred dependency locking, container build and persistence. The integrated implementation now installs from the lockfile, builds canonical Svelte, packages runtime dependencies/fonts and mounts SQLite storage. Python 3.12 and Java 21 are declared on their respective QA/emulator CI jobs; they are not required in the application image. Remote CI and deployment acceptance still gate release.

Rollback uses a compatible prior application revision with the preserved persistent volume and a verified backup. Restoring a snapshot is an explicit offline operation, revokes old sessions and may restore older account passwords. Do not restore over a database that is still being written or assume an older executable understands a newer schema. See backend-operations.md and docker-local.md for recovery commands and local isolation.
