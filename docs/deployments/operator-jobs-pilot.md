Add one queue `liquidity-operator-jobs` with maximum concurrent dispatch one, rate one/second, maximum three transport attempts, minimum backoff10s, maximum backoff60s and maximum retry duration600s. Planning example, not a bill guarantee: 20 items/day ×30 days ×120 active seconds =72,000 CPU-seconds and36,000 GiB-seconds at the existing resources. At published request-billed rates of $0.000024/vCPU-second and $0.0000025/GiB-second, this is about$1.82 before free-tier credits, other traffic, storage, networking, logging or model charges. Three delivery attempts plus creation for600 tasks is2,400 operations: under$0.001 at$0.40/million before the account-wide first-million allowance. This is a normal-workload planning example, not a maximum with every transport attempt lasting the entire service timeout. A deliberately loose600 ×3 attempts ×150-second example would be270,000 CPU-seconds and135,000 GiB-seconds, about$6.82 before credits and other charges. Neither example is dollar metering or a hard spending cap. Existing budgets/alerts and provider attempt limits remain necessary.

## Rollback

Pause the queue first and prevent new job creation. Through authenticated job controls, explicitly cancel/fence every unfinished active job before routing rollback; verify persisted fences/cancelled states. Then disable the dispatcher/feature, route traffic to the preserved prior revision and stop the owned local worker if applicable. If authenticated cancellation is unavailable, acknowledge and monitor the bounded in-flight lease/handler drain window instead of claiming immediate fencing. Preserve drafts, job IDs, attempt history and consistent backups. In-flight provider work may have been billed; a cancellation or traffic rollback cannot undo that external call. Queue pause, environment changes and traffic routing alone do not increment persisted item fences: an already accepted handler may still commit during its valid lease. Only the explicit application cancellation/fence (or observed completed drain) establishes that boundary. Never delete the user volume/database to roll back UI code.
